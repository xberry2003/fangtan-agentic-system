# 访谈提纲准备技能

## 触发与范围
- 用户要求新生成调研提纲、访谈提纲、采访问题或访前问题时使用本技能。
- 提纲是访前准备，不是基于证据的调研成果报告，不调用报告模板工具，不要求已有材料。
- 如果已有本技能流程，先沿用已确认状态；只有用户明确重新开始才重置。

## 第一步：目标与方案
- 调用 start_interview_outline 打开选择清单；系统可能已自动开启，已有时不用重复调用。
- 简洁说明“先确认研究范围，再生成访谈提纲”。选择卡片由界面展示，不在回复里重复所有选项。
- 主题尚不明确时让用户在主题栏补充；行业已明确时直接带入，不重复问行业，不擅自选择目标或受访者。
- 使用原系统的行业、研究问题与受访对象选项，允许自定义其他项。
- 必须先走选择清单流程，用户点击确认前禁止输出任何提纲正文，包括“通用版”“初稿”“示例”“先给一份再细化”、问题清单和章节框架；即使用户要求直接生成或跳过流程，也必须先展示清单。
- 已有项目材料、历史提纲或旧对话不能替代本次范围确认；已知信息只用于预填，让用户确认。
- 未确认前只用1到3句解释下一步并等待选择，不能列出项目材料、报告模板来替代清单，也不能通过create_document、update_document或create_report绕过确认。

## 第二步：根据已确认范围生成
- 只有用户点击确认后（状态 confirmed）才生成。用户输入的说明、地点和时长均需考虑。
- 将目标转为3到5个具体研究问题，将问题对应到受访者能回答的真实经历。不能向普通消费者询问企业财务等超出其经验范围的问题。
- 写8到15道核心开放问题，每道附1到2条简短追问。按受访角色分组，避免把同一套问题不加区分地问所有角色。
- 优先问“最近一次”“当时如何处理”“能举例吗”“还有哪些做法”。区分事实、影响、现有替代方案、原因和待验证假设。
- 不诱导用户认可方案，不用“是否愿意用某功能”代替行为证据，不重复问已知行业。
- 围绕用户选定目标安排优先问题，控制在选定时长内；泛泛的行业宏观问题只能在确有相关专家对象时出现。
- 现有材料可作为背景，若引用必须读取真实内容。未给出的数据、姓名、日期和研究结论不编造；新生成的问题不能当作已完成访谈事实。
- 输出Markdown，含标题、访谈目标与范围、受访对象、建议时长、开场与录音授权、分组核心问题与追问、收尾、使用提醒。核心问题用编号列表，每题以问号结尾，追问用缩进列表。
- 调用 save_interview_outline，传入当前flow_id、revision、文件名和完整Markdown。不要用create_report或create_document替代此步骤。

## 第三步：归档与继续
- 保存工具会将同一份文件归档到材料“访前准备”，登记为报告页可编辑的提纲，并标记流程完成。
- 保存后简洁提示可打开编辑或带提纲录音，不再追加选择清单，不声称完成了实际访谈。
- 失败时不丢弃已确认选择；按原flow_id和revision重试，避免重复文件。
