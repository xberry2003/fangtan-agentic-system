# 体察 Studio

独立的本地项目，以项目为所有操作的归属。原项目仅作为参考，未搬入旧版页面、流程编排、运维接口、历史数据库及密钥。

## 本轮范围

- 首次进入选择项目，或仅填写名称新建项目。
- 自动恢复本浏览器上次使用的有效项目；URL 指定的有效项目优先。
- 当前项目内提供开始录音、上传材料、项目对话和「打开工作台」。
- 新项目使用独立 SQLite 数据库；重启后项目、文件和对话保留。
- 保留原有浮雕底图、光标擦除和字幕动效；支持移动端、减少动态效果偏好及浅深主题。
- 录音支持暂停与继续，可导入或从项目文字文档带入提纲。结束后先保存原音并尝试转写及生成访谈纪要；上传失败可重试、下载备份或明确放弃。录制期间音频暂存在本页，关闭页面前需要保存。
- 支持流式项目对话、录音后阿里云转写及模型生成访谈纪要；需配置对应服务并取得云端处理同意，服务失败时保留已有文件并可重试。访谈纪要及逐字稿保存在项目材料中，Markdown 和 TXT 可手动编辑、预览。材料已支持真实文件夹管理；多对话线程尚未实现；实时转写及本场提问清单见下文。

## 启动（Windows，所有依赖及缓存放在 D 盘）

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install --cache-dir D:/codex-deps/pip-cache -r backend/requirements.txt
npm --prefix frontend ci --cache D:/codex-deps/npm-cache
npm --prefix agent-runtime ci --cache D:/codex-deps/npm-cache
npm --prefix frontend run build
.venv/Scripts/python.exe -m uvicorn app:app --app-dir backend --host 127.0.0.1 --port 19001
```

打开 http://127.0.0.1:19001/ 。也可运行 `scripts/start.ps1`，它检查依赖和构建后在当前终端启动服务。开发界面执行 `npm --prefix frontend run dev`，API 仍需在 19001 运行。

本项目当前为本机单人使用，没有认证，必须保持 `127.0.0.1` 监听。未部署到服务器。

## 配置与数据

需要 AI 时将 `.env.example` 复制为 `.env`，填写 `TICHA_AI_KEY`、`TICHA_AI_MODEL`、服务地址以及 `DASHSCOPE_API_KEY`。服务端读取配置，不向浏览器传密钥。本次本机开发按需迁移旧项目的模型和转写配置至被忽略的 `.env`；不依赖原项目运行。

`data/studio.db` 保存项目和对话，`data/files/<项目ID>/<文件ID>` 保存原始文件。项目名称不是文件路径，不同项目的文件与对话分开查询。首页记忆仅保存项目 ID；后端是项目和材料的事实来源。当前没有删除项目入口。

仅复用原项目自实现的浮雕擦除组件、字幕组件及用户提供的背景图、字体。字体许可见 `frontend/src/assets/NotoSerifSC-OFL.txt`。其它首页、项目 API、数据层和基础工作台重新实现。

## Pi Agent 与 Kimi

悬浮助手通过后端调用 Pi Agent Core 1.2.0，使用 `.env` 中的 Kimi 配置。需要 Node.js 22.19 或更新版本。Pi 进程由 Python 按对话启动，不需要另开端口。密钥只在服务端读取，不发送到浏览器或保存到对话。

支持列出当前项目材料、读取 UTF-8 Markdown/TXT、根据用户要求新建 Markdown 文档，以及读取后修改已有文字文档。修改使用版本哈希检测冲突，旧内容保存在 `data/versions/<项目ID>/<文件ID>/`。工具操作显示在对话中，保存成功后材料列表自动刷新；未保存的手动编辑草稿仍保留。生成被停止或失败时，已经保存的文档仍保留。

当前不开放删除、跨项目访问、终端命令，以及直接理解音频、图片、PDF、Word 的工具；录音转写形成的文字稿可以读取。每轮最多 12 次工具调用、10 次模型请求，普通对话总处理上限240秒，报告任务480秒。

本轮已使用隔离临时项目验证真实 Kimi 流式回复及 Pi 新建文档，无需浏览器验证。

## 材料生成报告与编辑

悬浮助手已接入原系统四套固定模板：需求调研、公司研究、市场调研、竞品分析。输入“根据现场记录.txt生成报告”，可以在输入区选择模板或不套模板，也可用自然语言指定。未说明模板方式时助手先询问；套模板会保留完整章节，缺少材料的部分注明待补充。报告工具要求先读取来源材料，保存时校验来源版本和模板章节，自动补充材料索引。

报告是项目材料的一部分，标记为 report；通过“报告”页统一打开、编辑，也可从助手生成后的链接进入。访谈纪要同样标记为报告。当前材料页仍为同一项目文件归档，报告不另存一套副本。

报告编辑使用 Tiptap，以接近 Typora 的正文编辑形式显示 Markdown，支持标题、列表、表格、任务项、图片、撤销重做、目录定位及源码切换。图片插入后先归档到项目材料。Ctrl/Cmd+S 保存，未保存草稿保留在当前浏览器；保存检测文件版本，避免直接覆盖助手的新修改。编辑器按需加载。

材料文字提取支持 UTF-8/GB18030 文本、DOCX（含表格）及文字型 PDF。旧版 DOC、扫描 PDF、图片和音频不能直接当作文字证据；需先转换、OCR 或转写。不自动截断超限材料，不声称读取未能提取的内容。模板迁移来源为原项目 backend/report_templates.py。

## 材料文件夹与删除（本地 SQLite）

材料页现在为真实文件管理：默认创建访谈录音、文字资料、现场照片、参考文件、访前准备、访谈报告六个文件夹。首次升级自动归档原有文件，保持原文件ID、报告与录音链接。支持嵌套新建、上传文件/文件夹、面包屑、项目内搜索、列表/网格、图片缩略图、重命名、移动、勾选批量操作及ZIP打包下载。

文件夹、文件归属、来源和更新时间存入同一 `data/studio.db` 的关系表，原始文件继续位于 `data/files/<项目ID>/<文件ID>`，不会把大录音塞进SQLite。材料访问集中于 `backend/material_repository.py`；后续迁移PostgreSQL需要替换连接、SQL方言和迁移脚本，保持API及文件ID不变，而非已支持直接切换数据库。

删除确认会计算文件夹内文件总数，支持单项/批量/递归删除。先暂存磁盘文件，数据库提交失败时回退；成功后清理文件和历史版本。删除录音会移除对应访谈入口，已有逐字稿或纪要不连带删除；删除逐字稿/报告会清理对应访谈引用。已生成报告中的文字引用不自动改写，删除被引用图片会影响显示。页面不提供回收站恢复。首次升级前的SQLite备份保存在 `data/backups/`，这些历史备份不会随单文件删除自动清理。

默认只监听本机19001，未操作服务器或生产数据库。用户自行在浏览器验收。

## 访谈提纲技能

`agent-runtime/skills/interview-outline/SKILL.md` 是项目Agent的访谈提纲技能。提出“生成一份调研提纲”后，在流式说明结束后展示原系统“目标与方案”清单：研究主题、行业、研究问题、受访人群及自定义其他项，附地点、时长和补充要求。已识别行业直接带入，可更改；不加载报告模板选项。

清单草稿保留在本浏览器，已确认范围和流程状态保存到SQLite `outline_workflows`。确认后，Pi只开放读取背景材料和保存提纲工具，生成与所选目标、人群和时长匹配的开放问题及追问。未确认不能保存最终提纲；支持取消、失败后重试、版本校验和幂等保存。

生成的同一份Markdown文件归档到材料“访前准备”，以可编辑访谈提纲登记到“报告”页；编辑器可直接带入录音。`document_labels` 区分提纲和普通报告。已有提纲的编辑、分析及“根据提纲生成报告”等请求不应重新触发新提纲选择流程。

## 文档保存与恢复

编辑器的正文、标题、哈希版本和更新时间保存到SQLite `document_contents`，Markdown磁盘文件作为同一份文档的导出缓存。原有UTF-8 Markdown/TXT在首次打开时迁入，原文件ID保持不变；文件缓存缺失或变空时从数据库恢复。Agent和编辑器共用同一读写入口，旧版本写入会被拦截，删除材料时文档快照一起删除。

正文和标题停止输入约1.2秒后自动保存，也可Ctrl/Cmd+S立即保存。切换文档会尝试提交尚未保存的内容，浏览器同时保留未提交草稿；恢复时检测服务器版本冲突，不再让旧空草稿覆盖已保存内容。初始化及可编辑状态变化不会触发保存，读取失败时禁止编辑覆盖。报告页记住本项目上次打开的文档；目录默认收起，可在工具栏展开。新建文档使用站内对话框，并提供独立标题输入。

## 图文报告整合与处理反馈

当前Pi工具支持 `inspect_image`：将本项目PNG/JPEG/WEBP/GIF缩放后交给已配置的Kimi模型读取真实图像，保存可见事实和不确定性；可选 `.env` 中 `TICHA_VISION_MODEL` 覆盖图片模型，默认使用当前Kimi。视觉服务失败时明确返回错误，不把文件名当证据。图片说明按文件哈希存档；插图前检查当前项目、实际读取状态、文件版本与章节位置。

用户可直接要求“根据采访记录.md和现场照片文件夹内的照片，按照市场调研报告模板生成报告”。报告生成工具支持 `images`（图片ID、章节标题、图注），将真实项目图片插入报告对应章节，并将文字与图片都记入材料索引。无证据的模板章节保留并标注待补充。

悬浮助手显示动态思考、工具执行阶段和用时，服务端约每5秒发送等待心跳。报告任务增加未保存结果的后续执行检查，避免仅说“我先读取”就结束。成果链接通过SQLite `message_artifacts` 绑定到生成它的助手回复，不再堆在所有消息底部；删掉文件时关联链接同步清除。自动滚动只作用于对话区域，用户向上阅读时暂停跟随。

隔离真实Kimi联调已通过：1份Markdown采访材料+2张测试示意图，按市场调研模板生成报告，2张插图、完整模板章节、材料索引及本轮成果链接均验证成功。未使用用户实际材料进行测试。

## 模型错误与报告恢复

失败提示按输出截断、限流、超时、鉴权、网络和其他服务错误区分，附错误编号。服务端记录请求阶段与脱敏错误摘要，浏览器不接收底层诊断或密钥。Kimi普通请求对临时服务错误有限重试；图片请求的网络/429/5xx错误最多重试一次。

报告任务单次输出预算提升至16000 tokens，单次模型调用时限180秒、任务时限480秒。已保存报告之后的说明文字如果中断，仍返回已保存文档及入口，不误报整个报告失败。未保存时明确告知失败，不伪装完成。

本轮使用实际项目材料的隔离副本重跑，约150秒成功生成市场调研模板图文报告；生成结果作为新文档归档回原项目，未覆盖任何原材料。原失败由于旧版未记录底层异常，无法事后断言具体原因。

## 项目文件作为对话附件

材料页的文件名称、报告列表及助手项目材料中的文件可以拖入发送框；材料页勾选后拖动可一次附加多个文件（最多20个）。也可在助手项目材料中点击加号附加。发送前可移除附件。引用不复制或重新上传文件，文件ID在后端校验归属并保存到SQLite message_attachments，后续对话保留附件上下文。Agent必须调用已有工具读取真实内容，附件本身不授权修改或删除。

## 带提纲访谈、实时转写与提问进度

报告编辑页提供醒目的“带此提纲开始访谈”按钮。进入前先提取真实问题、默认全选；可取消部分问题，确认后新建一场访谈，麦克风仍需用户点击开始并确认授权。录音页选择或导入提纲也使用同一问题选择弹窗，未发现问题时不填充虚构示例。

录音使用MediaRecorder保存原始音频；另一个静音AudioWorklet音频图输出单声道PCM，通过后端WebSocket中继发送至阿里云Paraformer。密钥留在后端。实时通道失败不会中断原录音；暂停时结束本次转写连接，继续后新开连接，结束时收取尾部结果。录音结束仍执行完整文件转写作为归档逐字稿，实时文字仅用于现场辅助。

依据已结束的实时语句，Kimi判断选中问题是否实际被问出，自动勾选；允许手动覆盖误判，不把“提到关键词”或“已经回答”当成提问。该识别不保证说话人区分，现场人员可手动修正。所选问题及自动/手动进度随访谈保存在SQLite interview_question_progress，重开历史访谈可查看。无提纲录音同样可直接开始并使用实时文字。

新增配置可选 DASHSCOPE_REALTIME_URL（默认北京区 dashscope WebSocket 地址），沿用现有DASHSCOPE_API_KEY；依赖websockets。开发代理启用ws转发。协议参考：https://help.aliyun.com/en/model-studio/websocket-for-paraformer-real-time-service 。本轮不打开浏览器，真实服务使用合成静音检查任务启停、合成文本检查问题匹配，不采集用户麦克风或使用用户录音。

## 对话技能入口与隔离

发送框的“+”打开技能菜单，提供图标与文字的访谈提纲、报告生成。选择后以技能标签加入本轮，发送时可以补充要求和拖拽附件；不填文字时也可直接发送技能。报告模板下拉不再常驻底部，而是在对话中的报告确认卡片选择（含不套模板），来源文件可一并勾选。

报告生成规则位于agent-runtime/skills/report-generation/SKILL.md，访谈提纲继续使用独立的interview-outline/SKILL.md。两套流程分别存在SQLite的report_workflows与outline_workflows，不共用表单、模板状态或保存工具。切换技能取消另一套待确认流程，版本检查拒绝旧卡片继续执行。Pi运行时和Python工具入口分别校验生成阶段的工具白名单；提纲不能调用报告模板或报告保存工具，报告不能调用提纲保存或普通文档写入绕过入口。消息技能标签保存到message_skills，刷新后仍可识别调用的技能。

## 项目内多条对话与后台任务

体察助手新增对话管理：项目内创建独立会话，历史消息迁入默认会话，记住上次打开的会话，未发送草稿按会话保留。文件仍属于项目，聊天历史、技能确认与报告模板状态按会话隔离。

POST消息时在SQLite事务中申请运行名额：当前本地单用户总共最多2条生成任务，同一会话最多1条。第三条会收到429且不保存重复用户消息，不自动排队。后台任务通过asyncio独立执行，事件以顺序号存入chat_run_events，浏览器只订阅输出；刷新、关闭悬浮窗、页面/项目/聊天切换和网络暂断不会取消任务，可从断点重连。只有调用手动终止API才主动取消运行，终止时保留已有文件与未完成文字。模型正常完成或报错也会更新终态。

该后台执行器用于当前单个uvicorn进程；浏览器重连可恢复流，但服务进程重启/崩溃不能继续原模型进程，旧运行会标为interrupted并保留历史事件，不能冒充仍在执行。未来多服务进程部署需共享任务队列与用户级配额；当前未部署服务器。
